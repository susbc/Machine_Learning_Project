# 回归任务端到端支持设计规格

日期：2026-09-09
状态：已完成对话设计，待用户评审书面规格

## 1. 背景

项目当前的 AutoML、手动训练和 Agent 工作流虽然在部分配置结构中声明了
`regression`，但实际训练链路仍以分类为中心：目标列通常按“两个唯一值为二分类，
否则为多分类”处理，模型工厂创建分类器，训练结果计算分类指标，前端也固定展示
Accuracy、AUC、F1、混淆矩阵和分类概率。

这种不一致会把连续数值目标错误地编码成大量类别，并可能导致训练失败、指标失真或
产物无法正确预测。本里程碑建立一套统一的任务规范，使回归任务在所有现有入口中
完成识别、训练、调参、保存、注册、恢复和预测，同时保持现有分类行为兼容。

## 2. 目标

本里程碑必须实现：

1. 支持自动识别二分类、多分类和回归任务，并允许用户显式覆盖。
2. 让 AutoML、手动训练和 Agent 工作流使用同一任务类型与能力规则。
3. 为回归任务提供 LightGBM、XGBoost、CatBoost、随机森林和线性回归。
4. 正确计算、展示和优化 RMSE、MAE 与 R²。
5. 让模型注册与预测实验室正确处理连续预测值。
6. 保持现有 API 路径、分类请求和旧分类产物兼容。
7. 通过后端、前端、集成、兼容性和安全回归验收。

## 3. 非目标

以下内容不属于本里程碑：

- 时间序列、异常检测、多标签分类和多输出回归。
- ElasticNet、神经网络或新的外部模型依赖。
- MLflow、数据版本、漂移监控、自动重训和分布式任务队列。
- AutoML 上传前预检或全局数据集服务重构。
- 前端 E2E、无障碍和国际化体系建设。
- 统一重写三个训练入口或改变现有 API 路径。

这些能力按已确认的后续里程碑顺序独立设计、实施和验收。

## 4. 总体方案

采用“统一任务规范层”方案，而不是分别修补各入口或重写整个训练引擎。

新增 `core/automl/problem_spec.py`，集中负责：

- 任务类型枚举和别名规范化。
- 目标列画像与自动推断。
- 用户覆盖与数据兼容性校验。
- 各任务类型支持的算法、指标、默认指标和优化方向。
- 可序列化的 `ProblemSpec` 响应与产物元数据。

AutoML、手动训练、Agent 工作流和模型工厂必须消费该模块，不得继续维护独立的
任务推断表。前端只渲染后端返回的规范与能力，不复制自动推断算法。

## 5. 任务规范

### 5.1 规范值

对外和产物中使用以下规范值：

- `auto`
- `binary_classification`
- `multiclass_classification`
- `regression`

为了兼容已有调用，输入可接受 `binary` 和 `multiclass` 别名，但响应始终返回完整的
规范值。无法识别的值返回 HTTP 422。

### 5.2 ProblemSpec

`ProblemSpec` 至少包含：

```json
{
  "schema_version": 1,
  "requested_type": "auto",
  "resolved_type": "regression",
  "source": "auto_inferred",
  "reason": "numeric_continuous_target",
  "target": {
    "column": "price",
    "dtype": "float64",
    "valid_rows": 1000,
    "unique_count": 947,
    "unique_ratio": 0.947,
    "integer_like": false
  },
  "capabilities": {
    "algorithms": ["lightgbm", "xgboost", "catboost", "random_forest", "linear_regression"],
    "metrics": ["rmse", "mae", "r2"],
    "default_metric": "rmse",
    "metric_directions": {
      "rmse": "minimize",
      "mae": "minimize",
      "r2": "maximize"
    }
  }
}
```

当用户显式选择任务类型时，`source` 为 `user_override`，`reason` 记录覆盖后的规范值。

### 5.3 自动推断

推断前排除目标为空的记录。有效目标少于两个不同值时拒绝训练。

规则按以下顺序执行：

1. 布尔、字符串或类别型目标：两个值为二分类，三个及以上为多分类。
2. 数值目标只有两个值：二分类。
3. 数值目标均为整数，且唯一值数不超过
   `min(20, ceil(sqrt(valid_rows)))`：多分类。
4. 其他数值目标：回归。

推断结果必须包含机器可读 `reason` 和用户可读解释。边界场景可由用户显式覆盖，
后端仍负责验证覆盖类型与数据是否兼容。

### 5.4 显式覆盖校验

- 二分类要求目标恰好有两个不同值。
- 多分类要求目标至少有三个不同值。
- 回归要求所有非空目标均可转换为有限数值。
- 分类沿用现有约束：每类至少两条记录，且训练集和测试集都能覆盖全部类别。
- 回归至少需要四条有效记录，且按请求的 `test_size` 划分后训练集和测试集都不少于
  两条记录，以保证 R² 可计算。
- 选择的算法和指标必须属于最终任务类型的能力集。

可在请求阶段判断的错误必须在任务入队前以 HTTP 422 返回，并指出字段、收到的值和
允许值。新增校验统一使用
`{"detail":{"code":"...","field":"...","message":"...","allowed":[...]}}`
结构；`allowed` 不适用时省略。训练过程中才可发现的异常将任务标记为 `failed`，
保存安全、可诊断的错误信息，不向客户端暴露堆栈和密钥。

## 6. 模型和指标

### 6.1 模型映射

现有算法标识在模型工厂中按最终任务类型映射：

| 算法标识 | 分类实现 | 回归实现 |
| --- | --- | --- |
| `lightgbm` | `LGBMClassifier` | `LGBMRegressor` |
| `xgboost` | `XGBClassifier` | `XGBRegressor` |
| `catboost` | `CatBoostClassifier` | `CatBoostRegressor` |
| `random_forest` | `RandomForestClassifier` | `RandomForestRegressor` |
| `logistic_regression` | `LogisticRegression` | 不支持 |
| `linear_regression` | 不支持 | `LinearRegression` |

前端和后端都必须阻止不兼容组合。运行时线程限制和日志抑制规则继续适用于对应的
回归实现。线性回归只提供其实现实际支持的参数，不伪造分类参数。

### 6.2 回归指标

所有回归训练结果返回：

- `rmse`：越小越好。
- `mae`：越小越好。
- `r2`：越大越好。

AutoML 的 `optimization_metric` 新增 `auto`、`rmse`、`mae` 和 `r2`。回归任务的
`auto` 解析为 `rmse`，二分类解析为 `roc_auc`，多分类解析为 `accuracy`。Optuna
对 RMSE/MAE 使用 `minimize`，对 R² 和分类分数使用 `maximize`。试验事件、排行榜
和最终结果存储并显示原始指标值，不依赖负分数的隐式约定。

回归结果不得包含 Accuracy、AUC、F1、混淆矩阵或阈值校准。指标无法计算时返回明确
诊断；不得用零、Accuracy 或其他替代值冒充结果。

## 7. 数据处理与训练流

### 7.1 共享准备流程

共享训练准备函数接收最终 `ProblemSpec`：

1. 删除目标为空的记录并验证目标。
2. 剔除已识别的键列。
3. 将特征中的无穷数替换为缺失值，并沿用训练集拟合的数值/类别预处理流水线。
4. 分类任务使用 `LabelEncoder` 和分层训练/测试划分。
5. 回归任务将目标转换为浮点数，不使用标签编码，采用确定性随机划分。
6. 预处理器只在训练集上拟合，避免数据泄漏，并随模型一同保存。

分类交叉验证使用 `StratifiedKFold`；回归使用带固定随机种子的 shuffled `KFold`。
分类任务要求每类样本数不少于 `cv_folds`，回归任务要求有效样本数不少于
`cv_folds`；不满足时在搜索开始前返回可解释错误。

### 7.2 AutoML

AutoML 创建任务时先解析 `ProblemSpec`，再确定默认指标和候选模型。用户显式提供的
候选模型或指标必须整体兼容；系统不得静默丢弃无效选择。

每个候选模型使用与任务类型匹配的搜索空间、交叉验证器和评分器。最终模型使用最佳
参数在训练集上拟合，在保留测试集上计算完整指标。任务快照、SSE 事件和结果均包含
最终任务类型，保证刷新恢复后语义不丢失。

### 7.3 手动训练

数据集上传时计算并保存自动 `ProblemSpec`。创建任务时可继续使用该结果，也可通过
`problem_type` 显式覆盖；覆盖后重新校验算法和目标。训练结果包含完整回归指标、训练
和测试样本数、特征列及特征重要性，不包含分类专属字段。

### 7.4 Agent 工作流

LLM 输出的 `task_type` 仅作为请求类型输入。任务规范层根据真实目标验证并解析；当
LLM 建议与最终类型不一致时，任务状态记录建议值、最终值和修正原因。

Agent 生成的 AutoML 配置必须经过同一能力校验。回归配置使用回归模型、回归搜索
空间、回归交叉验证和回归指标，不能继续进入分类训练器。

### 7.5 保存和推理

新产物增加：

- `artifact_schema_version: 3`
- `problem_spec`
- `problem_type`
- `metric_directions`
- 回归目标必要的类型元数据

回归预测返回浮点 `prediction`，`encoded_prediction` 和 `probability` 为 `null`。
分类预测保持现有标签反编码、概率和阈值行为。

`artifact_schema_version` 缺失或小于 3 的产物走现有兼容分支。兼容代码不能改写旧
文件；模型注册页将其标记为 legacy，并按已有分类指标降级展示。

## 8. API 契约

现有路径不变，新增字段均向后兼容：

- 新增只读 `GET /api/training/capabilities`，返回各规范任务类型支持的算法、指标、
  默认指标和优化方向，供 AutoML 与手动训练页面共同使用。
- AutoML multipart 请求增加可选 `problem_type`，缺省 `auto`；
  `optimization_metric` 支持 `auto` 和回归指标。
- 手动训练数据集上传和任务创建请求增加可选 `problem_type`。
- Agent 工作流沿用配置中的 `task_type`，但响应增加最终 `problem_spec`。
- 数据集、任务、任务结果、模型详情和预测响应在适用处增加 `problem_spec` 或
  `problem_type`。

旧客户端不发送新字段时继续工作。旧分类响应字段继续保留。手动训练回归结果中的
`confusion_matrix` 和 `threshold_calibration` 返回 `null`；AutoML 回归指标对象不
增加分类指标键。单条和批量回归预测中的 `encoded_prediction`、`probability` 返回
`null`。TypeScript 类型必须显式表达这些空值，不以宽泛 `any` 掩盖差异。

## 9. 前端交互

### 9.1 AutoML 与手动训练

- 新增任务类型选择器，默认“自动识别”。
- 自动模式不在浏览器复制推断规则；模型和指标保持“自动”，由后端解析。
- 显式模式从只读能力接口加载并过滤模型与指标；切换类型时清除失效值并提示用户。
- 任务创建后展示最终类型、判断来源、推断理由和目标统计。
- 回归结果使用 RMSE、MAE 和 R² 卡片，隐藏混淆矩阵、阈值和分类概率。

本里程碑不增加上传前预检接口。用户要强制类型时在提交前显式选择；自动模式在任务
创建时解析并立即随任务快照返回。

### 9.2 Agent 工作流

工作流页面同时展示 LLM 建议类型和后端最终类型。发生修正时显示原因，不能只在日志
中记录。

### 9.3 模型注册与预测实验室

模型注册页依据任务类型选择主要指标：分类保留现有优先级，回归优先展示当前优化指标
并同时显示 RMSE、MAE、R²。预测实验室对回归只展示连续预测值和输入诊断，不展示
概率、类别编码或正类比例。

缺少 `problem_spec` 的旧记录采用现有分类视图，并明确标记为 legacy。

## 10. 错误处理与可观测性

- 请求校验错误使用 HTTP 422，并提供稳定的字段级错误结构。
- 文件格式、目标列不存在等现有错误码保持不变。
- 任务执行错误进入 `failed`，任务和持久化状态中的错误信息一致。
- 日志记录任务 ID、最终任务类型、算法和指标，不记录上传数据内容或密钥。
- AutoML SSE 的失败事件包含可展示消息，刷新后的任务快照可恢复相同信息。
- 取消任务、服务重启恢复和任务保留策略继续适用于回归任务。

## 11. 多智能体实施策略

规格批准并生成实施计划后，按共享契约拆分工作：

1. 后端智能体：任务规范、数据准备、模型工厂、指标及 API。
2. 前端智能体：API 类型、任务选择、动态能力和结果展示。
3. 测试智能体：独立覆盖边界、集成、兼容性和负向场景。
4. 主智能体：先固定契约，再协调并行任务，整合改动和解决冲突。
5. 独立复审智能体：在实现完成后审查需求覆盖、代码质量和潜在回归。

共享文件由实施计划指定唯一负责人，避免多个智能体同时编辑。所有功能遵循测试驱动
开发：先提交能因缺失行为而失败的测试，确认失败，再做最小实现并重构。

## 12. 测试方案

### 12.1 单元测试

- 表驱动测试覆盖字符串、布尔、二值数值、低基数整数、连续数值和推断阈值边界。
- 覆盖别名规范化、显式覆盖和所有不兼容错误。
- 验证分类使用标签编码/分层划分，回归保留浮点目标/普通随机划分。
- 验证五个回归模型能拟合并返回连续预测值。
- 验证 RMSE、MAE、R² 数值及优化方向。
- 验证回归预测不执行标签反编码、概率或分类阈值逻辑。

### 12.2 API 和集成测试

- AutoML、手动训练、Agent 工作流分别使用确定性合成回归数据完成训练。
- 覆盖任务状态、SSE 事件、结果、保存、恢复、模型注册和单条/批量预测。
- 覆盖自动推断和显式覆盖两条路径。
- 覆盖算法、指标、目标数据不兼容的 HTTP 422 响应。
- 保留并运行所有现有分类 API 与旧产物兼容测试。

### 12.3 前端测试

- API 表单序列化新增任务类型和回归指标。
- 任务类型切换正确过滤和重置模型/指标。
- AutoML、手动训练、Agent 工作流显示最终任务规范。
- 回归结果只显示回归指标和连续预测；分类视图保持不变。
- 模型注册和预测实验室覆盖回归与 legacy 降级。

### 12.4 全量门禁

验收前必须以新鲜输出通过：

- Python 全量测试和项目现有覆盖率门禁。
- 新任务规范与回归核心模块达到至少 90% 行覆盖率。
- 前端 Vitest 全量测试。
- TypeScript 类型检查。
- Vue 生产构建。
- Bandit 中高危检查。
- `pip-audit`。
- 生产依赖 `npm audit`。

## 13. 验收标准

使用固定随机种子的线性合成数据进行最终验收：

1. 自动模式解析为 `regression` 并返回原因和能力集。
2. AutoML、手动训练和 Agent 工作流均能完成回归训练。
3. `linear_regression` 在该数据上的测试集 R² 不低于 0.95。
4. 结果包含有限的 RMSE、MAE、R²，且没有分类专属指标。
5. 保存、进程内恢复和模型注册后仍可预测。
6. 单条与批量预测返回连续浮点值，概率和类别编码为空。
7. 显式错误类型、算法或指标在入队前被拒绝。
8. 所有原有分类测试通过，旧模型仍可预测。
9. 第 12.4 节全部质量门禁通过且无新增安全问题。
10. 独立代码复审无未解决的高、中优先级问题。

任一标准失败时继续修复和复验，不进入下一个里程碑。
